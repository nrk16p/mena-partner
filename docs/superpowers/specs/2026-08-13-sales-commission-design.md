# ระบบสรุปยอดขายเซล + ค่าคอมมิชชั่น (เฟส 1: ดูอย่างเดียว)

วันที่: 2026-08-13 · ระบบ: mena-partner

## ปัญหา

เซลไม่มีที่ดูว่าตัวเองขายไปแล้วกี่คัน และได้ค่าคอมสะสมเท่าไหร่ ต้องไปถามหรือรอสรุปจากฝ่ายบริหาร
ระบบมีข้อมูลครบอยู่แล้ว (ใบเสนอราคาผูก `salesEmail`/`salesName` และมีสถานะ won) แต่ยังไม่มีการคำนวณค่าคอม

## ขอบเขต

**ทำ:** หน้าสรุปยอดขาย + ค่าคอมของเซลแต่ละคน (เซลเห็นของตัวเอง แอดมินเห็นทุกคน)
**ไม่ทำในเฟสนี้:** บันทึกการจ่ายเงินคอม, หน้าตั้งค่าอัตรา, export — ออกแบบให้เพิ่มทีหลังได้โดยไม่รื้อของเดิม

## กติกาค่าคอมมิชชั่น

ขั้นบันไดแบบ marginal — คันที่ N ได้อัตราตามช่วงที่ตัวเองอยู่ (ไม่ใช่ทั้งหมดเปลี่ยนตามขั้นล่าสุด)

| คันสะสมที่ | ค่าคอม/คัน |
|---|---|
| 1–5 | 2,000 |
| 6–10 | 3,500 |
| 11–15 | 4,000 |
| 16 เป็นต้นไป | 5,000 |

- **สะสมตลอดชีพ ไม่รีเซ็ตรอบ** — คันที่ N นับจากใบ won ใบแรกสุดของคนนั้น
- ตัวอย่าง: ขาย 7 คัน = 5×2,000 + 2×3,500 = 17,000 บาท · ขาย 16 คัน = 57,500 บาท

## นิยามการนับ

- **นับ 1 คัน เมื่อใบเสนอราคามีสถานะ `won`** (ปิดการขาย) — 1 ใบ = 1 คัน
- **วันปิดการขาย** = event ล่าสุดใน `timeline` ที่ action ลงท้าย "→ ปิดการขาย" ถ้าไม่มีใช้ `updatedAt`
  (ตรวจข้อมูลจริง 2026-08-13: ใบ won 17/17 ใบมี event นี้ครบ)
- **จัดกลุ่มผู้ขายด้วย `salesEmail`** (lowercase) ถ้าว่างใช้ `salesName` — กันชื่อพิมพ์ต่างกันแยกเป็นคนละคน
- ใบ won ที่ไม่มีทั้ง email และ name → กลุ่ม "ไม่ระบุผู้ขาย" แสดงเฉพาะแอดมินพร้อมป้ายเตือน ไม่ปนคอมของใคร

## สถาปัตยกรรม

คำนวณสดจากใบเสนอราคา ไม่สร้าง collection ใหม่ (ไม่มี 2 แหล่งความจริง ไม่ต้อง backfill)

```
lib/commission.ts        ← pure: ตารางอัตรา + ฟังก์ชันคำนวณ (ไม่แตะ DB)
  COMMISSION_TIERS
  commissionForNth(n)         → ค่าคอมของคันที่ n
  commissionTotal(count)      → ค่าคอมสะสมเมื่อขายไปแล้ว count คัน
  nextTierInfo(count)         → อีกกี่คันถึงขั้นถัดไป และขึ้นเป็นเท่าไหร่
  buildSalesCommission(rows)  → สรุปรายคน + รายการรายคัน

app/api/quotations/commission/route.ts   ← อ่าน quotations(won) → เรียกฟังก์ชันข้างบน → กรองตามสิทธิ์
app/quotations/commission/page.tsx       ← UI
components/sidebar.tsx, command-palette  ← ลิงก์เข้าหน้าใหม่
```

## สิทธิ์การเห็น (กรองฝั่ง server)

| บทบาท | เห็นอะไร |
|---|---|
| `salesperson` | เฉพาะของตัวเอง (จับคู่ด้วย email จาก session) — ข้อมูลคนอื่นไม่ถูกส่งมาที่ browser |
| `admin` / `superadmin` / `finance` / `fleet` | ทุกคน + กดดูรายคันของแต่ละคน |
| `viewer` | เข้าไม่ได้ (403) |

ต้องเพิ่ม `/quotations/commission` ใน allowlist ของฝ่ายขายใน `components/sidebar.tsx`
(ปัจจุบันเซลเห็นได้แค่ `/price-list` กับ `/quotations`)

## หน้าจอ

1. **การ์ดสรุปของฉัน** — ขายแล้วกี่คัน · ค่าคอมสะสมรวม · อัตราปัจจุบันต่อคัน · อีกกี่คันถึงขั้นถัดไป (ขึ้นเป็นเท่าไหร่)
2. **ตารางรายคัน** — คันที่ N · วันปิดการขาย · เลขที่ใบเสนอ · ลูกค้า · ทะเบียน/เบอร์รถ · ราคาขาย · ค่าคอมคันนั้น · สะสม (คลิกเปิดใบเสนอราคา)
3. **ตารางอัตราขั้นบันได** ท้ายหน้า ให้เห็นกติกาโดยไม่ต้องถามใคร
4. **(แอดมิน) ตารางสรุปทุกคน** ด้านบน — ชื่อเซล · จำนวนคัน · คอมรวม · อัตราปัจจุบัน · คลิกเพื่อดูรายคัน

## ความเสี่ยง / ข้อควรระวัง

- **ค่าคอมคำนวณสด** — ถ้ามีคนแก้สถานะใบเสนอราคาย้อนหลัง ยอดคอมจะเปลี่ยนตาม (ยอมรับได้ในเฟสดูอย่างเดียว ถ้าจะจ่ายเงินจริงตามยอดนี้ ควรเพิ่ม ledger ในเฟส 2)
- **ลำดับคันสำคัญกับเงิน** — ใบที่ไม่มี event ปิดการขายใน timeline จะ fallback ไป `updatedAt` ซึ่งอาจเลื่อนถ้ามีการแก้ใบภายหลัง
- ตอนนี้ยอดกระจุกที่เซลคนเดียว (16/17 ใบ) — ตัวเลขบนหน้าจะดูเอียง เป็นภาพจริงของข้อมูล ไม่ใช่บั๊ก

## เฟสถัดไป (ยังไม่ทำ)

บันทึกการจ่ายคอม (งวด/สถานะจ่ายแล้ว) → เพิ่ม collection `commission_payouts` มาทับได้ทันที เพราะการคำนวณแยกเป็น pure function อยู่แล้ว
